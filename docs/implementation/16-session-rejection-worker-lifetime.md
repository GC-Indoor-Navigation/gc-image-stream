# 세션 인증 거부와 relay 워커 수명 분리

## 실제 반복 검증에서 드러난 문제

7-B를 여러 세션에 걸쳐 반복하던 중, Stream의 매칭은 정상인데 Processing에 새로운 job의 이벤트가 하나도 생기지 않는 상황이 발생했다. 상태 조회 결과 relay client의 running은 false이고 마지막 오류는 `relay v2 disabled: SESSION_TOKEN_SCOPE_INVALID`였다.

이전 세션 종료와 relay 재연결이 겹치면 캐시된 이전 credential로 hello를 보낼 수 있다. Processing이 이를 거부하는 것은 맞지만, Stream은 모든 non-retryable hello 거부를 워커 전체의 영구 종료로 처리하고 있었다. 그 결과 이전 세션의 거부가 이후 정상 세션까지 막았다.

## 수정 범위

인증 credential이 있는 연결에서 `SESSION_TOKEN_SCOPE_INVALID`를 받았고, 현재 전송 중이거나 결과 미확정인 작업이 없을 때만 해당 ELIGIBLE 후보를 REJECTED로 종료한다. 동일 후보를 재시도하지 않고 워커는 다음 후보를 기다린다.

프로토콜·설정 불일치 같은 다른 영구 오류는 기존대로 중단한다. 이미 전송되어 결과가 미확정인 작업도 이 분기로 폐기하지 않는다. 그런 작업은 reconciliation 계약을 유지해야 하므로, 단순히 거부 상태로 바꿔 성공한 것처럼 다음 job으로 넘어가지 않는다.

## 검증과 남은 경계

회귀 테스트는 미전송 후보의 제한된 퇴출, 동일 후보 재시도 방지, 미확정 전송 유지, 다른 영구 오류의 중단 동작을 확인한다. 관련 relay client 테스트 13개를 통과했다.

이 수정은 세션 단위 거부가 전역 워커를 불필요하게 종료하는 문제를 다룬다. Main 장애 도중의 TTL 경계와 미확정 작업 복구 전체는 별도 7-C 검증 대상이다.

후속 반복에서는 Processing 쪽에 비정상 연결 종료 전 LIVE job lease가 남는 별도 문제도 확인했다. 이 수정은 그 소유권을 강제로 해제하지 않는다. 최종 7-B 검증 전 Processing 프로세스를 한 번 재시작해 메모리 상태만 정리했으며, 해당 자동 복구는 7-C에 남겼다.
